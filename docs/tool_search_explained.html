OpenAI Agents SDK Hosted Tool Search

ToolSearchTool is a tool finder, not the business tool.

It lets the model search a declared tool catalog at runtime, load the relevant tool definitions, and then call only the tools needed for the current request.

What happened in our demo

The demo now declares two namespaces. Think of each namespace as a toolbox with a label and a short description.

course_progress

Tools for student status and recommendations.

  • get_student_progress
  • recommend_next_step

course_content

Tools for week topics and learning resources.

  • get_week_topic
  • list_course_resources

For the default prompt, the model needs both toolboxes: progress data from course_progress and learning-resource data from course_content.

End-to-end flow

1. User prompt Ask about student progress, resources, and next action.
2. Tool search The model asks to load relevant namespaces.
3. Load tools The API returns the function schemas inside those namespaces.
4. Execute tools The model calls only the functions it needs.
5. Final answer The assistant writes from actual tool outputs.

Run items

The Run items section is not from the model response text. It comes from the Agents SDK RunResult.new_items list. Our helper in src/demo_helpers.py loops through that list and prints a readable trace of what happened.

Run item Meaning
tool_search_call_item The model asked tool search to load one or more paths/namespaces.
tool_search_output_item The hosted tool search returned the tool definitions that were loaded.
tool_call_item The model actually called a loaded function tool.
tool_call_output_item Your Python function returned output back to the model.
message_output_item The model wrote the final assistant message.

Tool search does not execute every function to find the best one. It searches names, descriptions, namespace descriptions, and schemas. Real execution only happens when a later tool_call_item appears.

Multiple toolboxes

Yes, you can have multiple toolboxes. In the Agents SDK, that means multiple tool_namespace(...) calls. You still add only one ToolSearchTool() to the agent. 

course_progress_tools = tool_namespace(
    name="course_progress",
    description="Student progress and next-step recommendation tools.",
    tools=[get_student_progress, recommend_next_step],
)

course_content_tools = tool_namespace(
    name="course_content",
    description="Course content tools for weekly topics and learning resources.",
    tools=[get_week_topic, list_course_resources],
)

agent = Agent(
    name="ToolSearchDemo",
    model="gpt-5.5",
    tools=[
        *course_progress_tools,
        *course_content_tools,
        ToolSearchTool(),
    ],
)

Do not add one ToolSearchTool() per namespace. The SDK validates hosted tool search as one search tool with one or more searchable surfaces.

When to use it

Good fit

  • You have many tools or large schemas.
  • Tools are naturally grouped by domain, such as CRM, billing, or course content.
  • You want lower tool-schema token usage per turn.
  • You want to defer hosted MCP servers or namespace groups until needed.

Probably unnecessary

  • You only have two or three simple tools.
  • Every user request always needs the same tools.
  • You are teaching basic function tools for the first time.
  • Your target model does not support tool_search.

Try it

uv run python src/tool_search_demo.py

If your OPENAI_MODEL is gpt-4.1-mini, this demo uses TOOL_SEARCH_MODEL=gpt-5.5 because the API rejects tool_search with gpt-4.1-mini.
